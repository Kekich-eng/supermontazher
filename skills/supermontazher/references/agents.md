# Сессии, STATE.md и агенты

Сессии не объединяются: каждая начинается с чистой памяти. Цель — чтобы новая сессия входила в ролик за минуту.

## STATE.md в папке каждого ролика

`video/<ролик>/STATE.md` — точное состояние одного ролика. Obsidian и память общие, здесь только этот ролик.

- **Новая сессия читает его первым**, до хаба и lessons. Нет файла — создай по шаблону ниже.
- **Обновляй на каждой остановке ⏸** и в конце сессии: где остановились, что готово, решения автора с причиной, следующий шаг. Коротко, без истории правок.
- Блок между `<!-- make.py: начало -->` и `<!-- make.py: конец -->` пишет `make.py` сам (последняя сборка, предупреждения, где черновик). Руками его не правь.

```
# <Название>: состояние ролика
## Где остановились      1–3 предложения
## Что готово (файлы)    пути
## Решения автора        что одобрил / отверг и почему
## Следующий шаг         одно действие, кто делает (я / автор)
```

Образец: `video/animaciya/STATE.md`.

## Отдельная сессия на этап

| Этап | Сессия | Что передаёт следующей |
|---|---|---|
| Сценарий | «сценарист» | `youtube-ai/scenario-<ролик>.md`, список материалов в STATE.md |
| Запись и монтаж | «супермонтаж» шаги 1–4 | готовый mp4, `edit.json`, STATE.md |
| Упаковка | агент `montage-packager` или отдельная сессия | файлы в `youtube-ai/` |

Длинная сессия переполняется и забывает начало. Этап закончен — обнови STATE.md и предложи автору новую сессию на следующий этап (карточкой start_session).

## Агенты для тяжёлой рутины

Агент делает работу у себя и возвращает короткий итог, поэтому листы кадров и длинные тексты не забивают память основной сессии. Ему нужен полный бриф: папка ролика, что сделать, в каком виде вернуть.

| Агент | Когда звать | Параллельно с чем |
|---|---|---|
| `montage-checker` (sonnet) | после `python make.py`: проверить `review/draft_sheet.jpg` и другие листы против `edit_resolved.md` | пока я правлю следующую сцену |
| `montage-packager` | монтаж одобрен: описание, теги, закреп, srt, пост, промпт обложки | пока идёт финальный рендер (`make.py --full`, ~13 мин) |
| `general-purpose` + бриф | поиск музыки на Mixkit по тегам (3 кандидата по 20 с в `music/`), покадровая запись HTML через `rec/record.mjs`, перерасшифровка окон `win.py` | пока я пишу код композиции |
| `codex:codex-rescue` | ревью кода композиции перед полным рендером (`codex.md`) | пока идёт черновик |

Файлы агентов: `~/.claude/agents/montage-checker.md`, `montage-packager.md` (их видно в новых сессиях; в сессии, где их только что создали, — `general-purpose` с тем же текстом).

Правила:
- Визуал, раскладку и стиль решаю я, агент только проверяет или готовит черновик (так же, как с Codex).
- Итог агента — не доказательство: проблему из его списка смотрю сам по кадру, тексты упаковки перечитываю перед отправкой автору.
- Два агента не пишут в одни и те же файлы. Рендер (тяжёлый GPU) одновременно только один.
- Длинный рендер — в фоне (`run_in_background`), агент на упаковку — в это же время.

## Типовой цикл с make.py

```
python make.py --animatic     до рисования сцен: весь ролик заглушками (~1,3 мин), ритм смотрит автор
python make.py --build        правки якорей, секунды; смотрю edit_resolved.md
python make.py --scene s3     правил сцену: 9 кадров только её (~1 мин)
python make.py --audio        правка только звука: звук ролика за ~30 с (review/audio_mix.wav)
python make.py                черновик 540×960/30 (~3 мин) + телефон + лист по сценам
   └─ агент montage-checker проверяет лист, я тем временем правлю дальше
python make.py --full         финал (~13 мин, в фоне)
   └─ агент montage-packager пишет упаковку
```
